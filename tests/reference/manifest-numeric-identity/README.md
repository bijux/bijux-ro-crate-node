# Platform-dependent manifest numeric identity

These eleven complete crates qualify an input limitation, separately from ordinary parity and confirmed upstream defects. The unchanged Python capture came from CPython 3.13.12 and pandas 3.0.2 on macOS arm64. `arm-provenance.json` binds its portable bytes and the installed parser binary. Every input retains its original file-byte receipts.

Three cases return Node `incomplete`: rounded file-path collisions, an interpretation-dependent row location and the same collision through a renamed path column. Continuation must refuse them. Eight controls retain their complete original reports, including duplicate rejection, valid distinct paths, unused and discarded numeric columns, string-column fallback, numeric-name lookup and existing scalar/type interruptions.

The restriction is outcome-sensitive. The same file-list rules evaluate separate and fused decimal accumulation; only different findings, interruptions or inbound references cause refusal. No numeric spelling is rejected merely because it appears in an unused column. Ordinary deterministic numeric values remain unchanged.

`arithmetic.json` records forty independent primitive cases and official pandas source/wheel provenance. The installed arm64 wheel uses fused multiply-add. The official manylinux x86_64 wheel uses separate multiplication and addition. Neither is treated as a validation defect.

`precise-xstrtod.c` retains the pandas 3.0.2 conversion function under its BSD license. The capture driver substitutes exactly its two digit updates, compiles with contraction disabled and explicitly selects either ordinary arithmetic or standard C `fma`. Both C results must match their locked binary64 receipts. The fresh pandas wheel must match one entire qualified profile; per-value mixtures and unknown profiles fail. This checks portability without inventing Linux whole-parser reports.

Run the required source and arithmetic guards:

```sh
node tests/reference/manifest-numeric-identity/run.mjs
artifacts/reference/python-env/bin/python tests/reference/manifest-numeric-identity/capture-arithmetic.py
```

Use `BIJUX_VALIDATOR_MODULE` for an installed validator. The browser guard at `tests/browser/manifest/numeric-identity.mjs` checks actual Worker/Session refusals and exact continuation bytes in all three engines; it also accepts the standard explicit installed module bindings.

To recapture the original whole-parser reports on a fused build, run the unchanged
`tests/parity/oracle.py` with `inputs.json`, then pass its raw capture and the
fresh arithmetic receipt to `verify-capture.mjs`. The verifier refuses a separate
arithmetic receipt instead of relabelling another build's reports as the ARM
capture. The required portable guard itself runs on either platform.

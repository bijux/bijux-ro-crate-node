# Explicit prefixes in model selection

An explicitly declared prefix can expand without a trailing URI delimiter.
Dropping that flag during model identification can hide a second BIA class while
the original raw model token still passes validation.

Twenty complete requests retain six explicit reference corrections and fourteen
unchanged controls. Five previously approved flat crates have unchanged-Python
full-URI counterparts with equal PyLD expansions/canonical graphs and isomorphic
RDFLib graphs. Their corrected full reports equal those unchanged counterparts.
The single-model alias remains rejected by the original Pydantic type-token
validator; its independently captured diagnostic identifies that model correctly.

The reference correction calls the original context parser and changes only the
returned instance's prefix serialization. Context validation, terms, model and
profile code remain untouched. Source/request hashes, entity order, expanded
ID/type identity, restoration and complete outcomes are checked. The ordinary
parity comparator is unchanged.

Six embedded-map neighbors remain exact incomplete refusals. They are not newly
approved authoring forms: the metadata is not flattened, and the type/id map
variants also violate the corresponding indexing constraints. Container roles
are not propagated by this correction. The two accepted controls must hand off
their original selected bytes.

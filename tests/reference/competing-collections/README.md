# Competing RDF collection arcs

The unchanged merged Python reference can approve or reject the same metadata
when a collection cell has more than one distinct `rdf:first` or `rdf:rest` value.
The registered 151 complete crates retain their raw current-main observations
in `original.json`; `corrected.json` is a separate qualification.

`capture.py` verifies the current source method and correction hashes, accepts
only exact registered subsets in corpus order, and appends a cardinality guard
to metadata reference validation. It checks the caller, metadata path and bytes,
requires one observation per requested case, rejects instrumentation exceptions,
and restores the original method. Other parser stages and installed files stay
unchanged. Sharded parity runs qualify only their selected registered inputs.

The public corpus snapshot identifies itself as `qualified-main`, with one
explicit disposition and qualified record hash for each registered case. The
separate `original-crates.json` snapshot preserves raw current-main reports.
All other cases compare strictly against raw Python; the ordinary comparator
contains no exception selection. Reports count ordinary exact comparisons and
qualified collection comparisons separately.
